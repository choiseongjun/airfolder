# 메모네스티아 마케팅 전략

작성 기준: 2026-10-25, 사용자가 제공한 홍보 전략 이미지 5장.

이 문서는 홍보글·SNS 콘텐츠·영상·프로필·랜딩 카피를 만들 때 반드시 참조하는 기본 지침이다. 현재 사용자의 요청이 이 문서보다 우선한다. 제품의 기능과 실제 화면은 게시 시점에 다시 확인한다.

## 현재 제품 방향 — 2026-10-26 우선 적용

- 대상: 사진은 쌓였지만 다시 펼쳐볼 결과물로 정리하지 못한 사람.
- 필요한 순간: 여행·나들이·함께 보낸 하루를 돌아보고 간직하고 싶을 때.
- 약속: **사진과 이야기를 작은 디지털 추억책으로 만들어드립니다.** 사용자는 사진 1~8장과 한마디를 주고, 서비스가 표지·사진 페이지·마지막 편지를 배치한다.
- 혼자서도 완성본을 얻는다. 친구 초대, 캐릭터 선택, 보상은 첫 사용의 조건으로 소개하지 않는다.
- 현재 결과물은 페이지별 JPG 이미지와 ZIP 다운로드다. PDF·인쇄·배송·AI 대필·유료 주문이 제공된다고 표현하지 않는다. 사용자 문장을 그대로 사용하며 없는 기억을 지어내지 않는다.
- 다운로드 후 사진 서랍에 완성본을 비공개 보관할 수 있다. 보관은 선택이며, 기기 미리보기와 서버 저장을 구분한다.
- 핵심 검증: 사진 선택 → 한마디 입력 → 완성본 생성 → 다운로드 또는 보관. 수익성은 아직 검증되지 않았다.
- 제품은 **추억책**으로 유지한다. 커플·여행·가족·결혼식은 제작 계기와 예시이며 별도 제품으로 확장하지 않는다.
- 주요 메뉴는 **홈 / 내 추억책**만 둔다. 만들기는 하나의 명확한 버튼, 계정은 상단 보조 메뉴로 제공한다. 선물은 완성본에서 선택하는 행동이다. 비하인드·크루·캐릭터·보상은 주요 화면과 계정에서 노출하지 않는다. 기존 데이터와 직접 접근 경로는 유지한다.
- 감성은 사진·자신의 문장·종이 같은 여백·차분한 페이지 전환으로 표현한다. 기능 소개와 장식, 반복 CTA를 늘리지 않는다. 한 화면에서 다음 행동이 명확해야 한다.
- 공유 기능을 설명할 때 현재 지원하는 파일 전송과 아직 구현하지 않은 온라인 선물 링크를 구분한다.
- 선물하기는 디지털 JPG 페이지를 내려받아 메시지에 첨부하거나 지원하는 기기에서 파일 공유 창으로 보내는 방식이다. 자동 발송·인쇄 배송을 약속하지 않는다. 파일을 보낸다는 이유로 비공개 앨범이 공개되지는 않는다.
- 아래의 공동 여행편·초대 중심 예시는 기존 기능과 과거 실험의 참고다. 현재 랜딩과 홍보에서는 위 방향을 우선한다.

## 1. 홍보 전에 정할 세 가지

| 질문 | 작성할 내용 |
| --- | --- |
| 누가 읽을까? | 내 앱이 필요한 구체적인 사람 한 유형 |
| 언제 필요할까? | 그 사람이 지금 겪는 상황이나 불편 한 가지 |
| 쓰고 나면 무엇이 달라질까? | 기능명이 아닌 사용 전후의 변화 |

“모두가 쓰는 사진 공유 앱”처럼 대상을 넓게 잡지 않는다. 한 게시물에는 한 대상과 한 상황을 담는다. 서로 다른 대상의 이야기는 별도 게시물로 만든다.

## 2. 첫 줄은 앱 소개보다 불편·상황부터

독자가 “이거 내 얘기인데?”라고 느낄 문장으로 시작한다. 앱 이름과 기능 설명은 그다음에 짧게 연결한다.

| 피할 시작 | 사용할 수 있는 시작 |
| --- | --- |
| 사진 공유 앱 메모네스티아를 만들었어요. | 여행 끝나고 “사진 좀 보내줘”만 세 번째 말하고 있나요? |
| 사진 뒷면에 댓글을 남길 수 있어요. | 같이 간 여행인데, 친구는 어떤 순간을 제일 기억할까요? |
| 캐릭터와 앨범 기능을 추가했어요. | 그날 사진은 남았는데, 왜 그렇게 웃었는지는 벌써 가물가물해요. |

질문형을 억지로 반복하지 않는다. 짧은 실제 상황이나 관찰로 시작해도 된다. 없는 사용자 경험·성과·후기를 실제 사실처럼 쓰지 않는다.

## 3. 기능 이름 대신 쓰는 순간을 보여주기

“앨범 생성·사진 공유·캐릭터·메모”를 나열하지 않는다. 누가 어떻게 사용하고 어떤 결과를 얻는지 이미지와 글로 상상하게 한다.

예시 흐름:

1. 여행을 마치고 사진 한 장을 고른다.
2. “길을 잃었는데 오히려 좋았어”라는 내 기억을 남긴다.
3. 친구에게 링크를 보내 같은 날을 어떻게 기억하는지 묻는다.
4. 친구가 “네가 웃겨서 힘든 줄 몰랐어”라고 보탠다.
5. 사진뿐 아니라 서로의 시선이 남은 카드가 된다.

핵심 가치는 **사진을 모으는 기능을 넘어, 함께한 날을 각자가 어떻게 기억하는지 남기는 것**이다. 캐릭터는 이야기의 주인을 표현하고 감정을 전하는 보조 요소로 소개한다. 보상·조각·캐릭터 종류를 홍보의 첫 설명으로 앞세우지 않는다.

## 4. 대상과 필요한 순간별 콘텐츠

| 대상 | 필요한 순간 | 공감할 불편·마음 | 보여줄 결과 |
| --- | --- | --- | --- |
| 함께 여행한 친구들 | 여행 직후 사진을 주고받을 때 | 사진은 흩어지고, 서로 기억하는 장면은 다름 | 같은 여행에 서로 다른 한마디가 쌓인 카드 |
| 커플 | 데이트·여행을 돌아보거나 기념일을 앞둘 때 | 사진만으로는 그날의 마음을 다 담기 어려움 | 같은 사진 옆에 남은 두 사람의 기억 |
| 가족 | 나들이·생일 뒤에 사진을 정리할 때 | 평범했던 하루의 작은 이야기를 잊기 쉬움 | 사진과 가족의 말이 함께 남은 기록 |
| 친구 모임 | 생일·재회·모임 다음 날 | 단톡방에서 좋은 말과 사진이 금방 밀려남 | 다시 펼쳐볼 수 있는 사진과 한마디 |
| 일상을 기록하는 사람 | 한 달을 돌아볼 때 | 특별하지 않은 날도 오래 기억하고 싶음 | 사진 한 장과 내 문장으로 남기는 순간 |

커플·가족 등 개별 편집기의 동작을 여행편과 동일하다고 가정하지 않는다. 초대, 비회원 참여, 내보내기처럼 흐름마다 다른 기능은 해당 링크에서 실제 지원되는지 확인하고 표현한다.

## 5. 이미지·영상 원칙

- 설명 슬라이드만 나열하기보다 실제 앱에서 사용할 장면과 완성 결과를 보여준다.
- 첫 이미지에는 해당 대상이 공감할 사진과 짧은 문구를 담는다.
- 사진 앞면 → 뒷면의 한마디 → 친구의 기억이 더해진 결과처럼 변화가 보이게 구성한다.
- 영상은 첫 장면에서 상황을 드러내고, 한 가지 핵심 동작을 보여준 다음 결과와 행동 유도로 마무리한다.
- 현재 운영 화면을 사용한다. 예전 화면이나 아직 없는 기능을 완성된 서비스처럼 홍보하지 않는다.
- 예시 사진·대화는 설명용임을 알아볼 수 있게 한다. 실제 사용자 후기처럼 꾸미지 않는다.
- 개인 사진·이름·비공개 대화는 공개 사용이 허용된 범위만 사용한다.

## 6. 링크와 행동 유도

Threads의 기본 방식은 **본문에서 관심을 만들고, 프로필 링크로 연결하는 것**이다. 글 끝에는 “우리 여행으로 한번 남겨보고 싶다면, 프로필 링크에서 카드를 뒤집어보세요”처럼 다음 행동 하나만 안내한다.

- 프로필 링크가 실제로 설정되어 있는지, 목적지와 언어가 맞는지 먼저 확인한다.
- 여행 글은 여행 예시, 커플 글은 커플 예시처럼 게시물의 약속과 도착 화면을 맞춘다.
- 처음 온 사람에게는 완성 카드 체험을 먼저 보여준다. 초대받은 친구는 바로 해당 참여 화면으로 연결한다.
- 링크 유무가 노출에 영향을 준다는 내용은 첨부 자료 작성자의 경험이다. 플랫폼의 확정 규칙이나 보장된 알고리즘 효과로 단정하지 않는다.
- 프로필 링크 방식과 본문 링크 방식을 비교할 때는 주제·게시 시간·이미지 등의 차이도 함께 기록한다.
- 질문에 답하거나 링크를 보내는 행위도 사용자가 승인한 게시·응답 범위에서만 수행한다.

## 7. 게시물 작성 틀

작성 전에 다음 내용을 메모한다.

```text
대상:
필요한 순간:
지금의 불편 또는 마음:
사용 후 달라지는 점:
보여줄 실제 화면·사진:
도착 링크와 해당 화면에서 가능한 행동:
```

본문 순서:

1. 공감할 불편이나 익숙한 상황으로 시작한다.
2. 구체적인 장면 한 가지를 짧게 묘사한다.
3. 그 장면에서 앱을 쓰는 모습을 보여준다.
4. 완성된 결과가 주는 의미를 말한다.
5. 프로필에서 체험하기 등 행동 하나로 마무리한다.

여행편 예시 초안:

> 같이 간 여행인데, 친구는 어떤 순간을 제일 기억할까요?
>
> 나는 길을 잃고 도착한 바다가 생각나고,
> 친구는 그때 우리가 웃던 모습이 생각날 수도 있잖아요.
>
> 사진 한 장 뒤에 각자의 기억을 남기는 여행편을 만들었어요.
> 사진만 모으는 대신, 우리가 그날을 어떻게 기억하는지도 같이 남겨보려고요.
>
> 프로필 링크에서 카드를 뒤집어보세요.

위 글은 형식 참고용이다. 같은 문구를 반복 게시하지 말고 대상·상황·실제 화면에 맞춰 다시 쓴다.

## 8. 개발 과정과 피드백도 사용자 변화 중심으로

“버그 수정 완료”, “기능 추가”로 끝내지 않는다. 어떤 사용 불편을 발견했고 사용자가 이제 무엇을 더 쉽게 할 수 있는지 보여준다.

- 사진부터 골라야 해서 시작하기 어려웠음 → 완성 카드를 먼저 뒤집어보고 시작할 수 있음.
- 친구가 왜 들어와야 하는지 모호했음 → 같은 날을 어떻게 기억하는지 한마디를 부탁하는 흐름으로 바꿈.
- 캐릭터가 장식처럼 보였음 → 각자의 기억 옆에 등장하도록 연결함.

검증되지 않은 전환율 개선을 주장하지 않는다. 실제 의견을 인용할 때는 의미를 과장하지 않고 공개 가능 여부를 확인한다.

## 9. 성과를 보고 다음 홍보에 반영하기

[유입 계측 문서](growth-analytics.md)와 운영 데이터로 확인한다. 조회수·좋아요만으로 성공을 판단하지 않는다.

- 홍보 측면: 게시물별 노출, 반응, 프로필 방문, 추적 가능한 링크 유입.
- 체험 측면: 소개 진입, 화면이 보인 상태의 10초 체류, 카드 뒤집기, 만들기 시작.
- 사용 측면: 사진 선택, 미리보기, 저장, 초대, 친구의 실제 참여.

플랫폼에서 제공되지 않는 지표나 아직 구현되지 않은 단계는 측정된 것처럼 쓰지 않는다. 작은 표본, 계측 시작 시점, 운영자 테스트 유입을 구분한다. 체류 기록이 없다는 사실만으로 “즉시 이탈했다”고 단정하지 않는다.

한 번에 주된 가설 하나를 바꾼다. 예를 들어 “기능 소개보다 여행 직후의 불편으로 시작하면 카드 체험까지 더 많이 이어지는가?”를 확인하고, 기간·대상·카피·이미지·목적지·결과를 기록한다.

## 10. 게시 전 체크리스트

- [ ] 누가 읽는지 한 문장으로 설명할 수 있는가?
- [ ] 그 사람이 언제 필요한지 구체적인 상황이 있는가?
- [ ] 첫 줄이 앱 소개가 아니라 독자의 상황에서 시작하는가?
- [ ] 기능 나열 대신 쓰는 장면과 사용 후 변화를 보여주는가?
- [ ] 이미지·영상이 글의 상황과 맞고, 실제 제품 동작을 반영하는가?
- [ ] 예시와 실제 사용자 경험을 혼동시키지 않는가?
- [ ] 행동 유도는 하나이며 프로필·도착 링크가 정상인가?
- [ ] 해당 흐름의 로그인·초대·저장 조건을 정확히 표현했는가?
- [ ] 사용자에게 승인받은 게시·응답 범위인가?
- [ ] 결과를 확인할 지표와 비교할 가설이 있는가?

## 참고 자료

사용자 제공 이미지의 다섯 원칙을 메모네스티아에 적용해 정리했다.

1. 앱을 쓰는 모습을 상상하게 만드세요.
2. 다운로드 링크는 프로필에.
3. 누가 언제 필요할까?
