# Memonestia 관리자 운영

운영 관리자 주소는 [https://memonestia.xyz/admin](https://memonestia.xyz/admin)입니다. 사이트 안에서 직접 로그인해 사용하며, Google Cloud 콘솔이나 Cloud Shell은 관리자 화면이 아닙니다. 개발 서버에서는 `http://localhost:3000/admin`으로 접속합니다. 이 작업으로 생성한 관리자 아이디는 `memolumi-admin`이며, 임시 비밀번호는 저장소 밖의 소유자 전용 파일에만 저장했습니다. 첫 로그인에서 16자 이상의 새 비밀번호로 변경해야 신고·삭제 자료를 볼 수 있습니다. 비밀번호는 채팅, Git, 신고 메모에 적지 마세요.

## 관리자 화면

- **신고 검토:** 검토 대기·숨김/정지·기각/해제로 구분합니다. 신고 상세에서 해당 자료를 확인하고 사유를 기록한 뒤 숨김, 기각, 작성자 정지를 선택합니다. 사진·영상 미리보기는 관리자 세션을 확인하는 비공개 경로이며 신고와 관계없는 파일은 조회할 수 없습니다.
- **이의 제기:** 숨김 해제는 사진·기록을 비공개로 유지합니다. 작성자 이용 정지는 별도의 이용 정지 메뉴에서 사유를 남기고 해제합니다. 콘텐츠를 복원한다고 계정 정지까지 자동 해제하지 않습니다.
- **계정 삭제:** 본인이 확정한 요청 중 5분이 지난 건만 실행합니다. 개별 처리 또는 오래된 순서로 최대 10건을 처리합니다. 실제 계정·원본·미리보기·기록·댓글·멤버십·인증 계정이 삭제됩니다. 다른 활성 멤버가 있는 공유 앨범은 소유권을 이전하여 그 멤버의 자료를 유지합니다.
- **실패 재시도:** 의존 서비스나 권한 오류가 있으면 요청과 실패 상태를 남깁니다. Firebase 관리 설정이 없으면 회원의 파일을 삭제하기 전에 중단합니다. 설정을 고친 다음 재시도합니다. 외부 저장소 삭제는 트랜잭션으로 되돌릴 수 없으므로 일부 삭제 후 실패한 경우에도 요청을 유지하여 나머지를 재시도합니다.
- **작업 이력:** 관리자 로그인·비밀번호 변경·신고 결정·정지 해제와 계정 삭제 요청 접수·시작·재시도·실패·완료를 기록합니다. 처리자, 대상 식별자, 시각, 시도 횟수와 안전한 오류 코드가 남으며, 삭제/신고/접속 이력별로 조회할 수 있습니다. 웹·예약 작업·CLI 모두 같은 삭제 코어에서 기록하며, 완료 로그는 계정 데이터 삭제와 같은 DB 트랜잭션으로 저장합니다. 비밀번호, 인증 토큰, 파일 내용은 기록하지 않습니다. 이력은 30일 후 조회에서 제외하고 정기 실행으로 제거합니다.

일반 회원/게스트 로그인으로는 관리자 API에 접근할 수 없습니다. 관리자 세션은 HttpOnly·SameSite=Strict 쿠키와 서버 저장소의 해시로 관리하며 4시간 후 만료합니다. 비밀번호 변경은 모든 관리자 세션을 폐기합니다. 로그인 시도는 서버 인스턴스 전체에서 제한하며 비활성 계정은 즉시 접근이 거부됩니다. 공개 회원가입이나 웹 관리자 생성 API는 없습니다.

## 서버 연결

기존 Firebase 프로젝트의 서비스 계정에 인증 사용자 삭제에 필요한 권한을 부여해야 합니다. 프로젝트 전체 소유자 권한이나 다른 프로젝트의 키를 사용하지 마세요. 키 파일은 저장소 밖의 비공개 폴더에 저장합니다.

`snaproom-ad17b` 프로젝트의 전용 서비스 계정 `memolumi-account-deletion`을 생성해 연결했습니다. 커스텀 역할 `memolumiAccountDeletion`에는 `firebaseauth.users.get`, `firebaseauth.users.delete`만 포함하며, 해당 계정에 다른 프로젝트 역할이 없는 것을 확인했습니다. 콘솔 생성 오류는 사용자가 승인한 Cloud Shell 설정으로 해결했습니다. 키는 소유자 전용 로컬 폴더와 기존 Vercel `airfolder` 프로젝트의 Production Secret에 보관합니다. Cloud Shell의 임시 키 파일은 로컬 연결 검증 후 제거했습니다.

```powershell
node scripts/configure-deletions.mjs --service-account-file C:/private/location/firebase-service-account.json
```

이 명령으로 프로젝트와 키 형식을 확인한 후 로컬 `.env.local`에 `FIREBASE_SERVICE_ACCOUNT_JSON`을 저장했습니다. `CRON_SECRET`은 기존 값을 유지했습니다. 운영 호스팅에도 두 값을 **서버 전용 Secret 환경 변수**로 등록하고 배포했습니다. 키를 교체할 때도 동일하게 로컬과 운영 값을 변경하고 재배포해야 합니다. 키 원문은 출력하지 않으며, `NEXT_PUBLIC_`에 넣지 마세요.

`vercel.json`의 작업은 매일 00:00 UTC(한국 09:00)에 `/api/maintenance/account-deletions`를 실행하도록 정의되어 있으며, 운영 배포 후 Vercel에서 등록 및 활성화 상태를 확인했습니다. Hobby 플랜은 지정 시간부터 한 시간 범위에서 실행될 수 있습니다. 실행 실패와 잔여 요청은 운영 중 확인해야 합니다. 요청량이 많으면 더 자주 실행하는 내구성 있는 작업 큐가 필요합니다. Firebase 관리 설정이 없거나 실패/잔여 요청이 있으면 예약 실행은 비정상 상태를 반환합니다.

관리자 계정 추가는 서버 접근 권한이 있는 운영자가 다음 명령으로만 수행합니다. 기존 계정 또는 자격 증명 파일을 덮어쓰지 않습니다. Windows에서는 출력 폴더의 ACL을 소유자만 접근하도록 먼저 설정하세요.

```powershell
node scripts/provision-admin.mjs --username NEW_ADMIN --credentials-file C:/private/location/new-admin.txt
```

## 검증 및 현재 상태

- `node scripts/test-admin.mjs`: 실제 SQL과 API를 사용하되 모든 DB 변경을 롤백하고 외부 Firebase/저장소는 가짜 의존성을 사용합니다. 일반 회원 접근 거부, 초기 비밀번호 변경, 세션 폐기·만료·비활성, 요청 출처, 로그인 제한, 신고 미리보기 범위, 제재와 해제, 삭제 실패·재시도와 다른 멤버 자료 보존을 검증합니다.
- `node scripts/test-deletion-concurrency.mjs`: 두 DB 연결로 동시 실행 차단과 실패·성공 후 잠금 해제, 재시도 및 로그 순서를 확인합니다. 생성한 임시 DB 행만 정리하고 실제 Firebase나 파일 저장소에는 접근하지 않습니다. 운영 검증에서 발견한 연결 풀의 세션 잠금 잔류 문제를 방지하기 위해 삭제 코어는 트랜잭션 종료 시 자동 해제되는 잠금을 사용합니다.
- `node scripts/test-safety.mjs`, `npm test`, `npm run build`: 기존 안전 기능과 전체 단위 테스트, 프로덕션 빌드를 확인합니다.
- 관리자 스키마 018과 `memolumi-admin` 계정은 설정된 DB에 적용했습니다. 실제 대기 신고·삭제 요청은 작업 당시 각각 0건이었습니다. 화면 검증용 임시 계정·신고는 검증 후 제거했습니다.
- 관리자 페이지는 데스크톱 브라우저에서 확인했습니다. 최신 `npm test` 50개, 관리자·안전 기능 SQL 통합 검증, TypeScript, 수정 범위 ESLint와 프로덕션 빌드가 통과했습니다. 모바일 너비 자동화는 실제 페이지 너비에 적용되지 않아 별도 검증이 필요합니다.
- 2026-10-15에 삭제 로그 보완(`1f56f27`)과 연결 풀 잠금 수정(`4d99261`)을 운영 배포했습니다. 최종 기능 배포 `5vjh9vYw9STzy2ZRWFYmUW7bqkna`의 Ready 상태를 확인했습니다. 운영 로그인 성공, 첫 비밀번호 변경 전 자료 접근 거부, 비로그인 접근 거부, 다른 출처 로그인 거부, 로그아웃을 확인했습니다. 실제 관리자 비밀번호는 변경하지 않았습니다.
- 실제 Firebase 임시 계정과 테스트 원본·미리보기 파일을 만들어 운영 `/api/account`에서 삭제를 요청하고, 임시 관리자로 해당 요청 하나만 `/api/admin/deletions`에서 처리했습니다. 5분 대기 제한, Firebase 계정 소멸, 저장소 파일 제거, DB 계정 제거, 완료 확인 기록, 요청·시작·완료 로그와 관리자 처리자 표시를 검증했습니다. 기존 사용자의 데이터는 삭제하지 않았습니다.
- 잠금 수정 배포 후 새로운 임시 계정으로 같은 삭제 검증을 다시 통과했습니다. 완료 확인 API가 `completed`를 반환했고, 인증된 자동 실행 경로를 연속 3회 호출해 모두 HTTP 200, 완료·실패·대기 0건, `firebaseConfigured: true`를 확인했습니다. 이는 예약 작업 경로를 수동 호출한 결과이며 다음 정시 실행이 이미 발생했다는 뜻은 아닙니다.
- 운영 관리자 화면에서 삭제 이력 필터와 요청·시작·완료 표시를 확인했습니다. 검증 후 임시 관리자, 테스트 계정·파일·완료 확인 기록·로그를 모두 정리했으며, 임시 관리자/계정과 삭제 대기는 0건입니다. 기존 `memolumi-admin` 계정은 활성 상태이고 첫 비밀번호 변경이 필요합니다.
- 테스트는 Firebase 이메일 계정으로 공통 삭제 경로를 검증했습니다. Google·Apple OAuth 로그인/재인증 및 Apple 토큰 해지 전체 흐름의 실제 기기 검증은 별도입니다. 앱 바이너리 재제출은 수행하지 않았습니다.
