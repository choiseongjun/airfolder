# 추억책 첫 경험 전환 및 검증

검증일: 2026-10-26. 로컬 구현 및 검증 완료, 이 작업에서 운영 배포는 진행하지 않았다.

## 방향

마케팅 기준은 [마케팅 전략](marketing-strategy.md)을 따른다. 사진을 보관할 공간보다, 사진과 자신의 이야기를 간직할 결과물로 만드는 경험을 먼저 제공한다.

기본 `/make` 진입은 소개 → 사진 선택 → 이야기 작성 → 완성본 확인 순서다. 사진은 1~8장, 이야기는 최대 600자이며 제목과 함께한 사람·날짜는 선택 입력이다. 기존 테마 및 꾸미기 진입은 유지한다.

## 실제 제공 범위

- 브라우저에서 표지, 사진별 페이지, 마지막 편지를 1080×1440 JPEG로 만든다. 사진 비율과 사용자의 문장을 보존한다.
- 로그인 없이 완성본 페이지를 확인하고 JPEG 묶음 ZIP을 내려받는다.
- 별도 동의 후 선택적으로 비공개 보관한다. 이 단계에서 서버에 올라가는 것은 완성된 페이지이며, 원본 선택 사진은 자동 업로드하지 않는다.
- 보관 요청은 안정적인 식별자와 완료된 업로드 목록을 사용해 재시도한다. 보관 시작 이후 내용을 고정한다.
- AI 문장 작성, PDF, 인쇄 주문, 결제는 구현하지 않았다. 수익성은 아직 검증되지 않았다.

## 확인 결과

- 자동 테스트 152개 통과, 프로덕션 빌드 및 대상 파일 ESLint 통과.
- 한국어에서 사진 2장으로 4페이지를 생성하고 실제 ZIP을 다운로드·압축 해제하여 표지와 편지 이미지를 확인했다.
- 영어에서도 완성본 ZIP 다운로드를 확인했다.
- 모바일 390px에서 가로 넘침과 소개 화면 레이아웃을 확인했다.
- 비공개 보관 후 메모 1개와 사진 4장의 연결 및 비공개 상태를 API로 확인했다. 검증용 앨범은 휴지통으로 이동했다.
- 생성기 테스트는 사진 순서, 비율 유지, 긴 문장 배치, 허용 사진 수, 손상된 이미지 거부를 확인한다.

## 후속 검증

운영 배포 후 소개 → 사진 선택 → 생성 → 다운로드 → 선택 보관의 실제 전환을 확인해야 한다. 무료 결과물을 받은 사용자가 어떤 추가 결과물에 돈을 지불할지는 별도의 가격 실험으로 검증한다.

## 웹 전체 주요 동선 개편

- 돌아온 사용자의 홈을 작품 중심 대시보드로 교체했다. 한국어·영어 공개 소개 페이지도 추억책 방향으로 통합했다.
- 공통 메뉴: 홈 / 내 작품(`/library`) / 선물하기(`/gifts`) / 내 계정(`/account`). 로그인도 같은 디자인으로 교체했으며 기존 인증 API와 계정 연결 동작을 사용한다.
- 내 작품에는 기존 앨범과 새 추억책을 모두 표시한다. 검색, 내가 만든 기록/초대받은 기록 필터, 페이지 넘기기, 기록별 ZIP, 전체 사진·메모 내보내기, 휴지통 이동을 제공한다.
- 기록의 첨부 사진 순서를 사용한다. 30개를 초과하는 기록은 추가로 불러올 수 있다. 추억책 표지 파일을 보관함 대표 이미지로 우선 표시한다.
- 공유는 완성 파일 전달 방식이다. 지원 기기에서는 파일 준비 후 별도 버튼으로 공유 창을 열어 사용자 동작 요건을 충족한다. 미지원 시 ZIP을 내려받으며, 파일 공유가 앨범 공개 범위를 변경하지 않는다. 묶음 파일은 80MB로 제한하고 큰 기록은 기존 분할 내보내기로 안내한다.
- 사진 추가·메모 수정·초대·공개 범위 등 기존 공동 앨범 관리는 작품의 원본 앨범 관리에서 제공한다. 크루·캐릭터·보상은 계정의 추가 설정에서 접근한다. 데이터 삭제나 기존 공유 권한 변경은 하지 않았다.
- 기존 `/crew/photos`, `/crew/settings`, `/crew/behind` 링크는 새 메뉴로 이동한다. 명시적인 `legacy=1` 원본 관리 진입은 유지한다. 지역별 인도네시아·필리핀 소개 페이지와 기존 공유 링크 수신 화면은 유지한다.

### 추가 브라우저 검증

- 최종 자동 테스트 155개, 대상 ESLint, 프로덕션 빌드 통과. 공개 소개의 클라이언트 URL 훅은 Suspense로 감싸 사전 렌더링을 지원한다.
- 사진 2장과 이야기로 4페이지 생성 → 비공개 보관 → 새 작품 뷰어 재진입 → 페이지 넘기기 → ZIP 다운로드를 실제 확인했다.
- 삭제 확인 UI에 앨범명을 입력해 검증용 앨범을 휴지통으로 옮겼다.
- 모바일 390px 가로 넘침 없음, 실제 휠 입력으로 내부 스크롤 이동, 하단 메뉴 고정 확인.
- 영어 선물·계정·로그인 화면, 한국어·영어 공개 소개, 기존 경로 이동, 추가 설정, 없는 작품의 안내를 확인했다.
- 실제 Google/Apple/Kakao 인증, 운영 배포, 메시지 수신 앱으로 최종 발송은 이번 검증에서 실행하지 않았다.

## 감성 중심 단순화 — 후속 로컬 변경

- 주요 메뉴를 홈 / 내 추억책으로 축소하고 계정은 상단 보조 버튼으로 이동했다. 선물하기 페이지는 직접 URL로 유지하되 주요 메뉴와 홈의 별도 홍보 섹션에서는 제외했다.
- 계정에서 비하인드·크루·캐릭터·보상 진입 링크를 제거했다. 기존 데이터와 직접 접근 경로는 유지한다.
- 홈의 책 예시는 3페이지를 직접 넘기는 형태로 변경했다. 예시임을 표시하고 키보드 조작 및 동작 줄이기 설정을 지원한다.
- 읽기 화면은 가운데 한 권에 집중한다. 함께 남긴 글, 관리, 삭제, 상세 내보내기를 접어서 표시하며 글 자체는 유지한다.
- 대상 ESLint와 프로덕션 빌드 통과. 브라우저에서 예시 페이지 전환, 한국어·영어 두 메뉴, 모바일 390px 가로 넘침 없음, 계정의 부가 기능 링크 제거를 확인했다.
- 읽기 레이아웃과 페이지 전환·본문 열기는 브라우저 한정 응답 fixture로 확인했다. 서버에 데이터는 생성하지 않았고 확인 후 fixture를 제거했다. 이번 변경에서는 운영 배포를 진행하지 않았다.

## 완성 화면 디자인 선택 — 후속 로컬 변경

- 완성 화면에 따뜻한 종이 / 필름 한 장 / 초록의 오후 / 깊은 밤의 편지 4가지 스타일과 무지 / 작은 점 / 체크 / 노트 4가지 패턴을 추가했다.
- 선택한 디자인으로 모든 페이지의 JPEG를 다시 생성한다. 미리보기, ZIP, 비공개 보관에 같은 파일을 사용한다. 사진 비율과 원문은 유지한다.
- 생성 성공 후에만 선택 상태와 페이지를 교체한다. 생성 중 다운로드·보관·중복 디자인 선택을 막는다. 보관이 부분적으로 진행된 경우 재시도 완료 전에는 디자인을 바꾸지 못한다.
- 보관 완료 후 디자인을 바꾸면 기존 앨범을 유지하고 별도의 새 보관본을 만든다. 새 보관에는 동의를 다시 받으며 이전 업로드 식별자를 재사용하지 않는다.
- 16가지 조합의 색·패턴·본문·사진 비율과 잘못된 옵션의 기본값 처리를 포함한 자동 테스트 157개 통과. TypeScript, 대상 ESLint, 빌드 통과.
- 브라우저에서 밤+체크 조합 생성·ZIP 다운로드·비공개 보관, 보관 후 필름 스타일 전환과 기존 보관본 유지, 390px 모바일 가로 넘침 없음을 확인했다. 다운로드 JPEG는 1080×1440이며 밤 배경색도 확인했다. 검증 앨범은 휴지통으로 이동했다.
- 운영 배포 전이다. 이전에 보관한 책은 이미 생성된 이미지이므로 새 제작 화면의 원본 사진이 없는 상태에서 디자인을 다시 편집하는 기능은 포함하지 않는다.
